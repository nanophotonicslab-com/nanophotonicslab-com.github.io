# NanophotonicsLab — General Audit (2026-06-20)

Scope: 13 lab tools (`src/pages/lab/`), shared compute (`src/lib/`), Pyodide
workers (`src/scripts/`), layout/config, PWA. Read-only audit, no changes made
except where noted. Claims below were spot-verified against source.

Severity: **P0** broken/credibility · **P1** real maintainability or UX cost ·
**P2** polish.

---

## P0 — Fix now

### 1. Favicon won't reach returning users (service-worker cache)
`public/sw.js` pins `CACHE = 'nanolab-v2'` and its `SHELL` precache lists only
`/favicon.svg`, not `/favicon.ico`. The fetch handler is **cache-first** for
`.ico`. So the `favicon.ico` we regenerated (commit `bc35ebe`) is served from
the stale `nanolab-v2` cache for anyone who visited before — the old dark logo
persists until the cache version changes.
**Fix:** bump `CACHE` to `nanolab-v3` (and optionally add `/favicon.ico` to
`SHELL`). One-line, unblocks the favicon work already shipped.

### 2. `heterostructures` is invisible to the brand/version system
The largest tool (`src/pages/lab/heterostructures/index.astro`, 5291 lines) is
**missing from `src/lib/tool-versions.ts`** and renders no `<ToolMeta>` /
`<ModelInfo>`. Result: no version badge, no citation button, no "updated" date —
the credibility scaffolding every other tool has. `ToolMeta.astro` silently
renders nothing when the tool key is absent, so the gap is easy to miss.
**Fix:** add a `heterostructures` entry to `TOOL_VERSIONS` and mount the two
components in the page header.

## P1 — Real cost

### 3. `downloadBlob()` duplicated across 8 tools
Same export helper copy-pasted (slightly divergent) in: mie-scattering:4792,
cylinder:4497, bpm:655, photothermal:1742, laser:2814,
plasmonic-nanoparticles:2557, rcwa:1106, heterostructures:3880 (+ a
`downloadBlobTmm()` variant at heterostructures:5127). ~200 lines of drift.
**Fix:** extract `src/lib/download.ts`, import everywhere.

### 4. Permalink / preset / reset coverage is uneven
Tools have diverged on shared scaffolding:

| Tool | PresetStrip | initPermalinks | Reset |
|---|---|---|---|
| mie-scattering | ✓ | ✓ | ✓ |
| cylinder | ✓ | ✓ | ✓ |
| heterostructures | ✗ | ✗ | ✓ |
| bem-solver | ✓ | ✓ | ✗ |
| laser | ✓ | ✓ | ✗ |
| photothermal | ✓ | ✓ | ✗ |
| electron | ✗ | ✓ | ✗ |
| photon | ✗ | ✓ | ✗ |
| plasmonic-nanoparticles | ✗ (inline btns) | ✗ | ✗ |
| rcwa | ✗ | ✗ | ✗ |
| bpm | ✗ (inline presets) | ✗ | ✗ |
| assistant / units | n/a | n/a | n/a |

Highest-impact gaps: **`plasmonic-nanoparticles` and `rcwa` have no
`initPermalinks()`** despite complex parameter sets — their states aren't
shareable, which undercuts the "send a colleague this exact run" value prop.
`bpm` and `plasmonic` define presets inline instead of using the shared
`PresetStrip` component.

### 5. Perf: no input debouncing on the heaviest page
`mie-scattering.astro` binds `render()` directly to `input` events
(e.g. ~2800–2814, 2477) — slider drag fires 60+ recomputes/sec with no throttle.
`rcwa.astro:1379` already does this correctly with `requestAnimationFrame`.
**Fix:** wrap the mie handlers in the same rAF-throttle pattern.

### 6. Perf: all tool logic ships inline per page, no splitting
Each `.astro` page inlines its full script (mie ≈4100 lines of JS). No shared
chunk, no cross-page caching. Acceptable for a static toolkit today, but it's the
same root cause as the node-editor obstacle (compute lives in pages, not libs) —
see the spec. Treat extraction as the long-term direction, not an urgent fix.

### 7. Accessibility: missing focus-visible on interactive controls
`.plot-tab` (mie ~955–962) and `.param-slider` (mie ~630–652, has
`outline:none`) define no `:focus-visible` style — keyboard focus is invisible
across ~40 tab/slider controls. The correct pattern already exists locally
(`.config-check:focus-visible`, mie ~754). **Fix:** add a shared
`:focus-visible` rule and apply to tabs/sliders across mie, rcwa, cylinder, laser.

## P2 — Polish

- **SEO:** `dist/sitemap-0.xml` lacks `/lab/heterostructures/` (stale build;
  page is linked from the lab index so still findable). Rebuild regenerates it.
- **Version dates:** every entry in `tool-versions.ts` shares `updated:
  '2026-06-10'` — looks like a copy-paste; dates no longer reflect real edits.
- **Duplicate import:** `plasmonic-nanoparticles.astro:936` re-imports MATERIALS
  (already imported at line 5).
- **a11y:** sliders lack `aria-labelledby`; rcwa radio-role buttons (42–49) lack
  `aria-label`.
- **`photon.astro`** export buttons use raw `toDataURL()`/blob instead of the
  shared download helper (folds into fix #3).

---

## Recommended order

1. **P0 #1 + #2** — favicon cache bump and heterostructures version entry. ~15 min, ships credibility.
2. **P1 #3** — `src/lib/download.ts` extraction. Mechanical, removes most duplication.
3. **P1 #4** — add `initPermalinks()` to `plasmonic` and `rcwa`.
4. **P1 #5 + #7** — mie debounce + shared focus-visible rule.
5. **P2** — batch the nits in one housekeeping pass.

Items #6 (inline-compute / no splitting) is intentionally deferred — it's the
same structural issue the node-editor spec addresses, so fold it into that
decision rather than fixing piecemeal.
