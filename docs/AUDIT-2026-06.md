# NanophotonicsLab — General Audit (2026-06-20)

Scope: 13 lab tools (`src/pages/lab/`), shared compute (`src/lib/`), Pyodide
workers (`src/scripts/`), layout/config, PWA. Read-only audit, no changes made
except where noted. Claims below were spot-verified against source.

Severity: **P0** broken/credibility · **P1** real maintainability or UX cost ·
**P2** polish.

---

## P0 — Fix now

### 1. Favicon won't reach returning users (service-worker cache)
`public/sw.js` pins `CACHE = 'nanolab-v2'` and its `SHELL` precache lists only
`/favicon.svg`, not `/favicon.ico`. The fetch handler is **cache-first** for
`.ico`. So the `favicon.ico` we regenerated (commit `bc35ebe`) is served from
the stale `nanolab-v2` cache for anyone who visited before — the old dark logo
persists until the cache version changes.
**Fix:** bump `CACHE` to `nanolab-v3` (and optionally add `/favicon.ico` to
`SHELL`). One-line, unblocks the favicon work already shipped.

### 2. `heterostructures` is invisible to the brand/version system
The largest tool (`src/pages/lab/heterostructures/index.astro`, 5291 lines) is
**missing from `src/lib/tool-versions.ts`** and renders no `<ToolMeta>` /
`<ModelInfo>`. Result: no version badge, no citation button, no "updated" date —
the credibility scaffolding every other tool has. `ToolMeta.astro` silently
renders nothing when the tool key is absent, so the gap is easy to miss.
**Fix:** add a `heterostructures` entry to `TOOL_VERSIONS` and mount the two
components in the page header.

## P1 — Real cost

### 3. `downloadBlob()` duplicated across 8 tools
Same export helper copy-pasted (slightly divergent) in: mie-scattering:4792,
cylinder:4497, bpm:655, photothermal:1742, laser:2814,
plasmonic-nanoparticles:2557, rcwa:1106, heterostructures:3880 (+ a
`downloadBlobTmm()` variant at heterostructures:5127). ~200 lines of drift.
**Fix:** extract `src/lib/download.ts`, import everywhere.

~~Highest-impact gaps: `plasmonic-nanoparticles` and `rcwa` have no
`initPermalinks()`.~~ **CORRECTION (verified 2026-06-20):** false positive — both
tools already implement complete shareable permalinks via a custom `Share` button
+ hash-based serialize/restore (`plasmonic:2643-2700`, `rcwa:1142-1179`).
plasmonic's is in fact *more* capable than the shared `initPermalinks` helper
(it captures tab/axis/sweep state, which the DOM-id-based helper cannot). The
real (minor) issue is **pattern inconsistency**: some tools use the shared
`initPermalinks` (`?query`) and others a custom `share-btn` (`#hash`). Not worth
forcing convergence. `bpm` and `plasmonic` also define presets inline instead of
using the shared `PresetStrip` component.

### 5. Perf: input debouncing on the heaviest page — mostly already done
**CORRECTION (verified 2026-06-20):** overstated. The main parameter path is
already throttled — slider/number `input` → `resetAndUpdate` → `scheduleUpdate`
→ `runScheduledUpdate` coalesces via a `rafPending` guard + `requestAnimationFrame`,
and electron mode adds a 140 ms debounce (`mie-scattering.astro:2580-2608`). The
only genuinely unthrottled path was the **Thermal view** handlers
(`~2811-2826`), where `renderIfThermal` called `render()` synchronously on every
`input` event. **Fixed (this commit):** `renderIfThermal` now coalesces through
`requestAnimationFrame`, matching the rcwa pattern.

### 6. Perf: all tool logic ships inline per page, no splitting
Each `.astro` page inlines its full script (mie ≈4100 lines of JS). No shared
chunk, no cross-page caching. Acceptable for a static toolkit today, but it's the
same root cause as the node-editor obstacle (compute lives in pages, not libs) —
see the spec. Treat extraction as the long-term direction, not an urgent fix.

### 7. Accessibility: missing focus-visible on interactive controls
`.plot-tab` (mie ~955–962) and `.param-slider` (mie ~630–652, has
`outline:none`) define no `:focus-visible` style — keyboard focus is invisible
across ~40 tab/slider controls. The correct pattern already exists locally
(`.config-check:focus-visible`, mie ~754). **Fix:** add a shared
`:focus-visible` rule and apply to tabs/sliders across mie, rcwa, cylinder, laser.

## P2 — Polish

All P2 items were re-verified on 2026-06-20. Most did not survive scrutiny:

- ~~**SEO:** sitemap lacks `/lab/heterostructures/`.~~ **DONE** — regenerated by
  the heterostructures build (`29b9a13`); page is now in the sitemap.
- **Version dates:** every `tool-versions.ts` entry shares `updated: '2026-06-10'`.
  **Decision: leave as-is.** Bumping to real git dates would now mislead — the
  2026-06-20 favicon/`download.ts`/focus-visible refactors touched 8 tool files
  without changing any physics. "Updated" should track model changes, not
  mechanical refactors. Only bump a tool's date when its model genuinely changes.
- ~~**Duplicate import:** `plasmonic` re-imports MATERIALS.~~ **FALSE POSITIVE** —
  the frontmatter import (line 5, used at 9–10 and in the template) and the
  client `<script>` import (used at 1203/1331/2640) are separate Astro module
  scopes; both are required.
- ~~**a11y — sliders:** REAL. ~33 range sliders across 5 tools have a visible
  `<label>` but no programmatic association, so they expose no accessible name.~~
  **DONE (this commit):** every `type="range"` input across the lab now has an
  accessible name — `aria-label` mirroring the visible label, `aria-labelledby`
  where the label text is dynamic (mie `#r-slider`, heterostructures
  `#tmm-angle-slider`), or a preexisting `<label for>` (mie thermal, materials
  VO₂). Mie's dynamic shell sliders get indexed names kept in sync by the
  renumber loop. ~~rcwa radio-role buttons lack `aria-label`~~ —
  overstated: those buttons have visible text content ("1D-RCWA", order numbers)
  which already provides the accessible name.
- ~~**`photon.astro`** export buttons use raw blob code.~~ **DONE** (`b8e909a`):
  folded into `src/lib/download.ts`.

### Net result of the audit
Of the original P1 findings, the genuinely-actionable ones (download dedup,
focus-visible) were fixed; **two P1s (permalinks ×2) and the P1 debounce were
false positives or overstated** — the tools already had the capability. Lesson:
the fan-out audit was good at pointing at files, but its conclusions (often from a
single grep) had a low hit rate and were verified against source before acting.

### New: mobile revamp (out of audit scope, gated)
Raised 2026-06-20. The layout reflows to one column on mobile, but breakpoints
are reimplemented per tool (768/900/700px) and control panels / chart canvases /
touch targets are unoptimized for small screens. Treated as a future redesign
behind the V2 approval gate — see the tracked issue, not a quick fix.
